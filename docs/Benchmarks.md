# Benchmarks

Head-to-head comparison of Lindblad against Qiskit / Qiskit Aer on a shared,
committed QASM2 corpus (`benchmarks/compare/circuits/`). Both engines run
natively: Lindblad through the `bench_compare_*` Google Benchmark binaries,
Qiskit/Aer through `benchmarks/compare/aer_bench.py` under a mirrored
protocol. This page is GENERATED by `tools/bench_report.py`; do not edit the
result blocks by hand.

Benchmark runs are refreshed periodically, not for every release: the library
version recorded under Environment identifies the run that produced this page
and may lag the current release version.

## Methodology

- Identical gate content: both engines load the same gate-only QASM2 files and
  append their own full-register terminal measurement where sampling is timed.
- Protocol: circuit loading and backend mapping excluded from timing; warmup
  then 5 repetitions; the median is reported. Sampling workloads use 256 shots,
  seed 42.
- Out-of-box configuration on both sides: Aer keeps gate fusion and its own
  threading; Lindblad keeps its compiled optimization flags. Settings are
  recorded under Environment.
- speedup = aer_ms / lindblad_ms: values above 1.00x mean Lindblad is faster.
- Every published table is gated on the result-parity checks below; a speed
  number on a wrong answer is not a result.

## Matrix Product State

Two families: a brickwork of random SU(4) blocks whose Schmidt rank exceeds every cap in the sweep, so all four caps truncate, and the layered scaling circuit, whose rank peaks at 2 and which therefore serves as a non-binding control. chi is the bond-dimension cap on both engines (Aer matrix_product_state_max_bond_dimension). Lindblad uses BDC SVD, its default. `lb svd share` is the fraction of the row's own median spent in the bond-split ladder, and `lb splits` the number of splits it made. The share counts the verification each split is held to, so it bounds what a faster SVD kernel could remove rather than estimating it. Aer exposes no counterpart. Read the speedup on the brickwork rows with care: both engines get the same cap, but each applies its own weight threshold beneath it and neither reports the bond dimension it actually reached, so those rows compare two truncation policies as well as two implementations. Aer's cost grows sub-cubically in the cap where a split at that bond is cubic, which is what an effective bond below the cap would look like. Comparing the two on output accuracy at a binding cap is what would settle it, and that measurement has not been made.

## Reproducing

See `docs/BuildAndTest.md` (section "Comparison benchmarks") for the full
WSL command sequence: build the `bench_compare_*` targets, run each with
`--benchmark_repetitions=5 --benchmark_format=json`, run `aer_bench.py` and
both validation halves, then regenerate this page with `tools/bench_report.py`.
